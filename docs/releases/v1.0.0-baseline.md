# AFRP Architecture Baseline v1.0.0 Release Notes

## 1. Purpose

`v1.0.0-baseline` freezes the approved AFRP architecture, governance, engineering
standards, schemas, and wire contracts so autonomous implementation can proceed from a
single, versioned, machine-verifiable source of truth.

This is an **architecture baseline release**, distinct from the AFRP Core product tag
`v1.0.0`.

## 2. Scope

The release establishes:

- singular canonical ownership for 26 engineering concerns;
- standardized metadata for 36 protected artifacts;
- a 35-entry non-recursive SHA256 architecture fingerprint;
- a freeze/change policy with ADR and SemVer rules;
- a pull-request architecture review checklist;
- a repository-wide Definition of Done;
- executable governance validation in CI;
- a validated dependency map with no ownership cycles;
- compatibility with the existing EGP-2.0 genesis handshake.

## 5. Known Limitations

1. `03-engineering/120_ENGINEERING_OPERATING_SYSTEM.md` contains a diagram label
   `EPS-1.0`; canonical prose and schemas use `ERS-1.0`.
2. Source architecture displays `EDR-10..12`; machine ledgers use
   `EDR-010..012`.
3. The Constitution filename alias is historical and resolved by ADR-0002; no alias
   file is created.
4. Existing protected files retain their native metadata/header formats. Complete
   normalized metadata is stored in the sidecar registry to preserve their hashes.
5. `buf` and cargo remain documented toolchain waivers on the genesis host; substitute
   gates are active.

Items 1-2 are recommended for a future ADR-governed patch baseline. They do not block
implementation.

## 6. Mutable After Freeze

Capability status, traceability evidence links, repository health, Work Package
lifecycle results, evidence records, implementation code, tests, CI, build locks, and
release records remain controlled mutable under their canonical schemas/processes.
They cannot override frozen architecture.

## 7. Next Milestone

**Phase 2 - Governed EOS implementation and autonomous Work Package execution.**

Entry conditions are satisfied:

- baseline integrity machine-verifiable;
- ownership and dependencies unambiguous;
- WPS/ERS contracts frozen;
- Definition of Done and PR review procedure active;
- baseline gate integrated into CI;
- no blocking governance defect.

The current repository already contains a functioning EOS implementation, so Phase 2
can use `afrp boot`, `afrp plan`, `afrp validate`, `afrp evidence`, `afrp health`, and
`afrp run` immediately. Future implementation must remain bounded by the frozen
architecture and approved Work Packages.
